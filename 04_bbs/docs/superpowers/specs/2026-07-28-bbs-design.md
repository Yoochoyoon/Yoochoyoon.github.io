# 게시판(BBS) 프로젝트 설계 문서

- 작성일: 2026-07-28
- 목적: 학생 학습용 프로젝트. 게시판 개발을 통해 CRUD 흐름과 풀스택 개발에 필요한
  기술(프론트-서버-DB-배포)을 이해하는 것이 목표.

## 요구사항 요약

- 로그인/회원가입 없음
- 글 작성 시 닉네임 + 비밀번호 입력, 글 수정/삭제는 비밀번호 검증 후 가능
- 이미지 첨부 가능한 글
- 글 목록 페이지네이션
- 글 제목 검색
- 조회수 표시
- 댓글 기능 (작성만 가능, 수정/삭제 불가)
- Vercel에 무료로 배포 가능해야 함 (비용 발생 서비스 사용 금지)

## 1. 아키텍처

```
브라우저(사용자)
   │
   ▼
Next.js 프론트엔드 (pages/) ── 목록/상세/글쓰기/수정 화면
   │  fetch('/api/...')
   ▼
Next.js API Routes (pages/api/) ── 요청 처리, 비밀번호 검증
   │
   ▼
Supabase
   ├─ Postgres DB (글, 댓글 텍스트 데이터)
   └─ Storage (이미지 파일)
   │
   ▼
Vercel에 배포 (프론트 + API 함께 호스팅, 전부 무료 티어)
```

**기술 스택**
- 프레임워크: Next.js (Pages Router) — Vercel과 배포 궁합이 좋고, 구조가 단순해
  CRUD 흐름을 이해하기 좋음
- 데이터베이스/파일 저장소: Supabase 하나로 통일 (Postgres + Storage, 무료 티어)
- 배포: Vercel 무료 티어
- 이미지 업로드는 API Routes를 거치지 않고 브라우저에서 Supabase Storage로
  직접 업로드 (Next.js API Routes가 파일 업로드보다 JSON 처리에 최적화되어 있기 때문)

## 2. 데이터 모델

**posts (게시글)**

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | 자동증가 숫자 (PK) | 글 고유 번호 |
| nickname | 문자열 | 작성자 닉네임 |
| password_hash | 문자열 | 암호화(해시)된 비밀번호 |
| title | 문자열 | 제목 (검색 대상) |
| content | 긴 문자열 | 본문 |
| image_url | 문자열 (nullable) | Supabase Storage에 올라간 이미지 주소, 선택 항목 |
| view_count | 숫자 (기본 0) | 조회수 |
| created_at | 날짜시간 | 작성일 (자동 기록) |

**comments (댓글)**

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | 자동증가 숫자 (PK) | 댓글 고유 번호 |
| post_id | 숫자 (FK → posts.id) | 어느 글에 달린 댓글인지 |
| nickname | 문자열 | 댓글 작성자 닉네임 |
| content | 문자열 | 댓글 내용 |
| created_at | 날짜시간 | 작성일 |

댓글은 삭제 기능이 없으므로 password_hash 컬럼 불필요.

## 3. API 설계

| 메서드 | 주소 | 역할 |
|--------|------|------|
| GET | `/api/posts?page=1&search=검색어` | 글 목록 조회 (페이지네이션 + 제목 검색) |
| GET | `/api/posts/[id]` | 글 상세 조회 (조회수 +1, 댓글 목록 포함) |
| POST | `/api/posts` | 글 등록 (닉네임, 비밀번호, 제목, 내용, 이미지주소) |
| PUT | `/api/posts/[id]` | 글 수정 (비밀번호 검증 필요) |
| DELETE | `/api/posts/[id]` | 글 삭제 (비밀번호 검증 필요) |
| POST | `/api/posts/[id]/comments` | 댓글 등록 |

이미지는 브라우저에서 Supabase Storage로 직접 업로드 후, 반환받은 URL을
`POST /api/posts`의 `image_url` 값으로 함께 전송.

비밀번호는 저장 시 해시(예: bcrypt)로 암호화하며, 수정/삭제 요청 시 입력값을
동일 방식으로 해시하여 저장된 값과 비교.

## 4. 화면 구성

```
pages/index.js           → 글 목록 (페이지네이션 + 검색창)
pages/post/[id].js       → 글 상세 (내용 + 이미지 + 조회수 + 댓글 목록/작성)
pages/post/new.js        → 글쓰기
pages/post/[id]/edit.js  → 글 수정 (비밀번호 확인 후 진입)
```

**주요 흐름**

```
[글 목록] --글쓰기 버튼--> [글쓰기 화면]
   닉네임/비밀번호/제목/내용/이미지 입력 → 이미지는 Supabase로 바로 업로드
   → 등록 버튼 → POST /api/posts → 성공 시 [글 목록]으로 돌아감

[글 목록] --글 클릭--> [글 상세]
   GET /api/posts/[id] 호출 (조회수 자동 +1)
   → 하단에 댓글 입력창, 댓글 목록 표시

[글 상세] --수정 버튼--> 비밀번호 입력 팝업
   → PUT /api/posts/[id] 로 비밀번호+수정내용 전송
   → 서버가 비밀번호 일치 확인 후 수정 반영, 틀리면 에러 메시지
```

## 5. 에러 처리

| 상황 | 처리 방식 |
|------|----------|
| 필수 입력값 누락 | 프론트에서 1차 검증 + API에서 400 에러로 재검증 |
| 수정/삭제 시 비밀번호 불일치 | API 403 반환 → "비밀번호가 틀렸습니다" 표시 |
| 존재하지 않는 글 번호로 접근 | API 404 반환 → "글을 찾을 수 없습니다" 화면 |
| 이미지 업로드 실패 | 실패 메시지 표시, 이미지 없이도 글 등록 가능 (선택 항목) |
| Supabase 연결 실패 등 서버 오류 | API 500 반환 → 공통 에러 메시지 |
| 페이지네이션 범위 밖 페이지 요청 | 에러 아님, 빈 목록으로 "글이 없습니다" 표시 |

## 6. 테스트 방식

학습 목표가 CRUD 흐름 이해이므로 별도 테스트 프레임워크 대신 수동 테스트
체크리스트로 검증한다.

- [ ] 글쓰기: 이미지 포함/미포함 각각 정상 등록되는지
- [ ] 글 목록: 페이지네이션이 정확히 넘어가는지, 제목 검색이 잘 되는지
- [ ] 글 상세: 조회할 때마다 조회수가 1씩 오르는지
- [ ] 글 수정/삭제: 비밀번호 맞으면 성공, 틀리면 실패하는지
- [ ] 댓글: 등록이 잘 되고, 수정/삭제 버튼이 없는지
- [ ] 없는 글 번호로 접근 시 404 화면이 뜨는지
- [ ] Vercel 배포 후 실제 배포 주소에서도 위 항목이 모두 동작하는지

## 범위 밖 (Out of Scope)

- 회원가입/로그인 시스템
- 댓글 수정/삭제
- 카테고리, 태그, 좋아요 등 부가 기능
